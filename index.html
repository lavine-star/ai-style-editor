Quick setup

三步接入其他 Vite 项目

目标项目需要是 Vite 开发服务，并且同事本机已经安装、登录 Claude Code。插件默认只在 mode === 'test' 时注入前端工具。

01

复制插件目录

把当前项目里的整个目录复制到目标项目，路径保持一致最省事。

需要复制
tools/ai-style-editor/
02

在 vite.config.ts 引入插件

把插件放进 plugins 数组，并按项目补充规则。规则越具体，AI 越不容易改错范围。

vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { dtAiStyleEditorPlugin } from './tools/ai-style-editor'

export default defineConfig(({ mode }) => ({
  plugins: [
    vue(),
    dtAiStyleEditorPlugin({
      enabled: mode === 'test',
      projectName: '你的项目名',
      projectRules: `
        当前项目使用 Vue3 + TypeScript + Vite。
        Vue 文件必须使用 <script setup lang="ts">。
        样式优先使用项目现有样式体系。
        不修改业务逻辑，优先修改选中元素附近结构。
        不修改 API、store、router、mock 数据或构建配置。
      `
    })
  ]
}))
03

增加 test 模式启动脚本

同事只需要运行这个脚本。普通 pnpm dev 不会注入 AI 样式调试按钮。

package.json
{
  "scripts": {
    "test": "vite --host 0.0.0.0 --mode test"
  }
}
启动命令
pnpm run test

Options

常用配置项

大多数项目只需要配置 enabled、projectName 和 projectRules。其他参数用于改 endpoint、源码目录、允许文件类型和 Claude 命令。

参数 默认值 用途
enabledconfig.mode === 'test'控制是否注入浏览器按钮和启用本地接口。
projectName当前项目出现在 AI prompt 里，帮助 Claude Code 理解项目。
projectRules通用前端样式规范写项目硬约束，例如 Tailwind 优先、禁止改业务逻辑。
sourceRootsrc限制源码定位范围，其他目录会被忽略。
allowedExtensions['.vue']限制可定位的组件文件类型。
protectedPathsrouter / stores / apis / mock写进 prompt，提醒 AI 不要修改这些路径。
commandclaudeClaude Code 命令名。如果同事用自定义别名，可以在这里改。
permissionModeacceptEdits传给 Claude Code 的权限模式。
requireComponentFiletrue要求必须定位到组件文件，减少误改范围。
Safety boundary

默认安全边界

这个工具是本地开发效率工具，不是线上能力。它的设计目标是让样式改动更快，同时把可执行范围压到最低。

只在启用模式注入当前配置只允许 test 模式显示悬浮按钮和调用接口。
生产构建无残留插件只作用于 Vite serve，不进入 production build。
浏览器不传命令后端固定调用 Claude Code，用户输入只作为样式要求。
限制源码定位组件文件路径必须落在 sourceRoot 且扩展名在允许列表内。
FAQ

接入时最常见的问题

如果按钮没出现，优先检查启动模式和 vite.config.ts。接口返回 403 通常说明当前不是启用模式。

为什么我运行 pnpm dev 没有按钮？

这是预期行为。当前建议只在 pnpm run test 的 mode === 'test' 中启用，避免普通开发或生产环境误触发。

其他项目不是 Vue 可以用吗？

可以作为 Vite 插件接入，但当前浏览器端源码定位主要依赖 Vue 组件实例信息。React 或普通 HTML 项目需要调整客户端里的组件文件定位逻辑。

能不能让 AI 改多个文件？

可以，但建议让 projectRules 写清楚“优先修改选中元素附近结构”。这个工具的优势是小范围样式调试，不建议让它做大重构。

同事没有 Claude Code 账号怎么办？

这个方案是本机 Claude Code bridge。同事需要自己安装并登录 Claude Code，否则后端无法启动 claude 命令。
