# 视频转透明 GIF 应用

一个简单易用的 H5 应用，可以将视频文件转换成透明背景的 GIF 动图。界面参考「帧刻 GIF Studio」，适配手机和电脑，转换全程在浏览器本地完成。

## 启动项目

无需安装前端依赖，在项目目录运行：

```bash
python3 -m http.server 8000 --bind 0.0.0.0
```

电脑访问 `http://127.0.0.1:8000/`。手机与电脑连接同一 Wi-Fi 后，访问 `http://电脑局域网IP:8000/`。macOS 可通过 `ipconfig getifaddr en0` 查看 Wi-Fi IP。请仅在可信局域网使用，不要将开发服务器暴露到公网。

支持透明 / 保留背景、帧率 / GIF 质量 / 缩放比例 / 背景移除阈值调节、自定义 RGB 与画面取色、实时进度和取消、棋盘格 / 白色 / 深色预览，以及下载与手机保存指南。默认按原视频完整时长转换，初始参数为 30 fps、质量 1、原始尺寸、阈值 30。Lucide 图标和 GIF 编码器均随项目本地加载，不依赖 CDN。

透明区域使用独立 Alpha 蒙版编码，并为 GIF 调色板预留透明索引，不再把移除区域涂成绿色。默认也清除手臂等围出的封闭背景；只有需要保留主体内部同色细节时才开启对应保护。

绿幕按色相、饱和度和绿色优势生成整帧透明蒙版，覆盖浅绿色、阴影、偏青的高饱和绿光与封闭空隙；不再只匹配单个 RGB 样本附近的颜色，也不再把残留背景涂灰。随后清理透明边缘两像素内的绿色压缩残留，并仅在保留的前景边缘减轻溢色。低饱和白发、肤色、浅青服装及蓝青服装分别限制，减少误删；同色且同饱和度的绿色主体细节仍可能被移除。阈值越大，绿色饱和度 / 绿色优势限制越宽松，阈值 0 保留精确颜色匹配。黑底、白底和保留背景模式不执行绿幕清理。

默认自动识别背景色，并在背景处理区域显示实际移除的颜色；也可直接选择「绿色背景 / 绿幕」。蓝幕使用色相限制与 RGB 容差，黑 / 白等其他纯色背景使用 RGB 容差。此功能是纯色抠图，不是 AI 人像分割，主体中与背景同色的部分仍可能被移除。

## 功能特性

✨ **核心功能**
- 📹 支持多种视频格式（MP4, WebM, MOV 等）
- 🎨 自动移除背景生成透明 GIF
- ⚙️ 可调节参数（帧率、质量、缩放、透明度阈值）
- 📱 响应式设计，支持移动端和桌面端
- 💾 一键下载生成的 GIF

🔧 **可调参数**
- **帧率 (FPS)**: 5-30 帧/秒，控制动画流畅度
- **质量**: 1-20，数值越小质量越高（文件越大）
- **缩放比例**: 0.1-1.0，控制输出 GIF 尺寸
- **透明度阈值**: 0-255，控制背景移除的敏感度

## 使用方法

1. **打开应用**
   - 启动本地服务后，在浏览器打开服务地址（不要直接双击 HTML，GIF 编码需要 Web Worker）

2. **上传视频**
   - 点击上传区域选择视频文件
   - 或直接拖拽视频文件到上传区域

3. **调整参数**
   - 根据需要调整帧率、质量、缩放和透明度阈值
   - 透明度阈值较小：只移除非常接近背景色的部分
   - 透明度阈值较大：移除更多相似颜色的部分

4. **开始转换**
   - 点击"开始转换"按钮
   - 等待处理完成（会显示进度）

5. **下载 GIF**
   - 预览生成的透明 GIF
   - 点击"下载 GIF"按钮保存文件

## 技术实现

### 背景移除算法
应用使用色度键控（Chroma Keying）技术实现背景透明化：

1. **采样背景色**: 选择背景色、从画面取色，或从第一帧边缘自动识别主要背景色
2. **颜色分类**: 绿幕结合色相、饱和度和绿色优势，区分绿色背景 / 高饱和绿光与低饱和前景；其他背景计算 RGB 欧氏距离，蓝幕额外限制色相
3. **透明蒙版**: 匹配背景的像素直接设 Alpha 为 0，默认处理整帧及封闭空隙，不把背景变灰
4. **压缩残留与溢色**: 使用初始透明蒙版清理两像素内的绿色压缩残留，避免级联侵蚀人物；只对保留前景的轮廓减轻溢色，GIF 仍使用二值透明
5. **透明蒙版编码**: 为调色板预留透明索引，透明像素不参与前景颜色量化，避免绿色色键残留与误删

### 使用的技术
- **HTML5 Canvas API**: 视频帧捕获和图像处理
- **gif.js**: GIF 编码和生成
- **Web Workers**: 多线程处理提高性能
- **原生 JavaScript**: 无框架依赖，轻量快速

## 优化建议

### 获得更好的透明效果
1. **选择纯色背景视频**: 单一颜色的背景（如绿幕、蓝幕）效果最佳
2. **调整阈值**: 根据视频背景调整透明度阈值
   - 背景色单一：使用较小阈值（20-30）
   - 背景色复杂：使用较大阈值（40-60）
3. **光照均匀**: 确保视频背景光照均匀，避免阴影

### 控制文件大小
1. **降低帧率**: 减少 FPS 可以显著减小文件大小
2. **降低质量**: 增加质量参数值（10-15）
3. **缩小尺寸**: 降低缩放比例（0.3-0.5）
4. **缩短时长**: 只转换视频的关键片段

## 常见问题

**Q: 为什么生成的 GIF 很大？**  
A: 尝试降低帧率、增加质量参数值、减小缩放比例。

**Q: 背景没有完全透明？**  
A: 调整透明度阈值，或确保视频背景是纯色。

**Q: 处理时间太长？**  
A: 缩短视频时长、降低帧率、减小缩放比例。

**Q: 支持哪些视频格式？**  
A: 浏览器支持的所有格式（MP4、WebM、MOV 等）。

```bash

```

验证不同编码质量下的逐像素透明蒙版、黑底素材的绿色主体保留、封闭背景清理、全透明帧、保留背景、绿光与浅绿残留真正透明；同时验证默认自动识别、带黑边的绿幕识别，以及阈值 30 / 80 / 200 / 255 下每个像素与人工定义的前景 / 背景蒙版一致，保留白发、肤色、浅青及蓝青服装与深色裤子。

已安装 FFmpeg 时，可运行实际 H.264 视频上传、自动识别、转换及下载的集成测试（也可用 `FFMPEG_PATH` 指定 FFmpeg 路径）：

```bash
node tests/green-screen.cjs
```

此测试使用合成绿幕素材与阈值 200，检查人物不同颜色保留、全部已知背景及封闭空隙透明、悬浮绿光与浅绿残留透明而不是变灰、偏青压缩边缘清理，以及 320 / 390 / 768 / 1440 像素宽度下没有横向溢出。测试产物保存到 `test-artifacts/`，不代表已验证用户的原视频。

### 实际原片验证与成品

本次另用用户提供的 1042×582、约 24.98 秒 MP4 验证了完整生产流程，并根据真实悬浮绿光调整偏青绿色的饱和度范围，保留低饱和浅青服装。使用默认 30 fps、质量 1、100% 尺寸、阈值 30 导出 750 帧透明 GIF。GIF 帧延迟按百分之一秒累计分配舍入，避免每帧 33.33 ms 都被舍入为 30 ms 而使视频加速。

- `outputs/green-screen-transparent.gif`：原尺寸、30 fps、完整时长的透明成品。
- `outputs/green-screen-transparent-preview.gif`：半尺寸、12 fps 的完整时长预览，便于手机查看。
- 原视频只读取，没有修改或复制到公开目录。

`outputs/` 和 `test-artifacts/` 为本地生成目录，已在 `.gitignore` 中排除，不随源码提交；克隆仓库后需自行转换生成。

可复用以下检查（需要 Playwright；Python 检查另需 Pillow、NumPy 和 imageio-ffmpeg）：

```bash
node tests/real-video.cjs /absolute/path/source.mp4
node tests/export-real-video.cjs /absolute/path/source.mp4
python tests/verify-real-video.py /absolute/path/source.mp4 outputs/green-screen-transparent.gif
```

最后一个检查针对本次原片：从独立解码的源帧确定明确绿幕区域，逐帧检查导出 GIF 的这些像素 Alpha 为 0、帧处置方式为清除旧帧，并检查人物头发 / 肤色 / 衣服 / 裤子的采样点及完整时长。人物采样位置针对这段素材，换其他视频时需重新标注，不能把此检查当作通用人物分割。

### 本地图片序列预览
